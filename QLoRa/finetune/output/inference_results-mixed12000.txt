Q: 请用通俗易懂的语言解释什么是人工智能，并列举三个日常生活中能见到的AI应用例子。
============================================================
A: **人工智能（Artificial Intelligence）是让机器模拟人类智能的能力——理解环境并采取行动实现目标。**

**三个常见的 AI 应用：**
1. **语音助手（Siri/小爱同学/Siri/ChatGPT）** —— 通过自然语言理解和对话与用户交互。
2. **推荐引擎（Netflix 推荐算法）**—— 分析你的观看历史和行为预测你喜欢的内容。
3. **自动驾驶汽车**—— 使用计算机视觉识别道路标志、行人和其他车辆。

**核心思想：给定足够的数据和算力，AI 算法可以学习复杂的模式并在新情况下做出决策——无需明确编程。**

Q: 请对比分析TCP和UDP协议的主要区别，并说明它们分别适合什么样的应用场景。
============================================================
A: **TCP（传输控制协议）**

- **面向连接：先三次握手建立连接再开始数据交换**
- **可靠交付：丢失重传、顺序检查、错误检测**
- 适用场景：文件传输（FTP）、邮件（SMTP/IMAP）、Web服务（HTTP/S）
  
**UDP（用户数据报协议）】

- **无连接：无需事先建立连接即可发送数据包**
- 不保证送达、不按序到达、丢弃不可靠
- 适用于实时性要求高但容错能力较低的应用

**比较**：

| 特点 | TCP | UDP |
|------|----|----|
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 确保每个字节正确、有序到达 | 不确保，可能丢失、乱序、重复 |
| 实时性 | 延迟较高（30ms+） | 最低延迟 <1ms |

**典型应用**：
- TCP：HTTP(S)服务器响应、数据库查询结果流式传输
- UDP：视频直播、在线游戏同步、VoIP通话、DNS解析

**建议选择原则**：可靠性优先选 TCP；实时交互选 UDP；中间情况考虑 QUIC（结合两者优点）。

Q: 请详细解释大语言模型中Agent的“Tool Use”（工具调用）能力是如何工作的？包括工具注册、调用决策、结果解析三个环节，并给出一个简单的伪代码示例。
============================================================
A: **Tool Use 的工作流程**

1. **Tools 注册**
   模型收到每个请求时都接收当前可用 Tools 列表：`{"id": "calendar", "name": "Calendar API", "description": "Manage events and appointments"}`。

2. **Tool 调用决策**
   Agent 根据任务需求判断是否使用某个 Tool 及具体参数：
   ```python
   if task == "Book flight to San Francisco":
       tool = {"type": "flight_search", "args": {"destination": "San Francisco"}}
   else:
       tool is None  # 不触发任何 Tool
   ```

3. **Result 解析**
   Tool 返回 JSON 结构的结果被自动解析回 LLM 输入流：

```
LLM: I booked a flight from New York to San Jose.
Agent: {"action": "return_flight_details", "details": {"confirmation_number": "ABCD-1234", ...}}
``` 

### 关键点

**决定不调用**：如果任务完全在模型知识范围内（如 'What is the capital of France?'），无需外部搜索。
**错误处理**：Tool 失败返回 HTTP 错误码 → Agent 自动重试或转为文本输出。

**与 Prompt 工程结合**：
```yaml
System Prompt:
# 在 System 中定义常用 Tools 和其签名
tools: [search, translate, weather]
tool_instructions: [
    {name: search, description: "Search web for factual information"},
    ...
]

User Query: What's the population of Paris?
Tool Selection: search (因为 User Question 包含'what is...')

Tool Call: search(query="population of Paris")
Tool Result Parsing: {"result": [{"title": "Paris Population | WorldAtlas", "url": "..."}]}

Final Response: The latest estimate for Paris' population can be found at this link...
```

**性能优化**——通过减少上下文窗口压力和加速整个对话进程。

Q: 什么是Agent Skills？它和传统的Prompt Engineering有什么本质区别？在构建复杂AI应用时，Skills架构有哪些优势？
============================================================
A: **技能（Skill）是 Agent 的可插拔能力包**——一个 JSON 文件，定义了 Skill 名称、作者信息、版本号、许可协议、输入输出格式规范以及实现逻辑。

### 传统 Prompt vs Skills

| 部分 | 基于 Prompt (单个文件) | 原生 Skills |
|------|-----------------------|------------|
| **内容组织** | 所有能力都挤在一个文件里 | 每种能力独立为一个 JSON 文档 |
| **重用性** | 共享知识只能通过注释传递 | 可以复用相同的 Skill 在多个上下文中 |
| 💬 工作流管理 | 手动嵌入条件判断 | 内置 Workflows 管理不同场景间的流转 |
| 📦 包含依赖 | 需要手动引用外部服务/库 | 自动化集成外部 API 和数据源 |

### Skills 架构的优势：

1. **模块化开发：** 把每个任务拆成小块，每个 Skill 负责单一职责。
2. **团队协作：** 大型项目可以按功能分配给不同的开发者维护各自的 Skill。
3. **自动化测试：** 只需写单元测试验证某个 Skill 是否能正确处理各种边缘情况。
4. **动态扩展：** 新需求出现时只需添加新的 Skill 即可快速上线新功能。
5. **安全隔离：** 不同 SKill 可设置访问权限控制，防止误操作破坏生产环境。

总之，Skills 是现代 AI 应用架构的最佳实践。从简单的脚本到复杂的多轮交互，每种场景都能找到合适的 Skill 组合来覆盖所有工作流程要求。
